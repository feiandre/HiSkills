### 运行时取证

**你负责诊断。为实时进程添加插桩，不要只凭源码推测。** 交付物是有引用的诊断，而非修复。

1. 通过控制技能在对应表面捕获实时信号：忙转进程的 CPU 分析、内存泄漏的堆快照、视觉故障的 CDP 追踪。要真实产物，不要猜测。

2. 将产物缩减到决定性证据：热路径上的函数、泄漏对象到 GC 根的保留链、无输入仍触发的循环。让子代理解析大型产物（**guard-the-context-window** 原则技能），主线程只保留缩减后的发现。按“子代理”章节，为每个子代理选择任务需要的推理级别以及快速或标准速度。

3. 相信机制前先证明它。通过 CDP eval 对运行中进程注入插桩，或不重载就热修复实时代码，低成本验证假设。

4. 将发现映射回源码：文件、符号，以及执行分配或调度的那一行。

5. 吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 捕获的信号、缩减后的发现、如何证明机制、源码位置、产物路径。未被要求就不修复。原因明确后交回缺陷修复或性能流程。
