### 爬山

**你负责指标与实验完整性。监督和审查，委派尝试。** 用于针对目标持续迭代改进一个可测量事物。一次性修复是 Bug 修复或性能问题；这里是一个循环。

核心纪律：一次变更、一次测量、保留或回退。绝不堆叠未测变更，也绝不靠代码阅读宣称胜利（**prove-it-works** 技能）。

1. 选择指标前奠定工作负载和架构。对目标运行 **how** 技能，说出可改变结果的现实维度，选择能复现用户抱怨的案例。不能复现先修复现。然后固定一个指标、更好方向及可检查停止谓词，目标必须配尝试次数下限，避免早期幸运结束运行。用户给了数字就用，否则共同确认。

2. 构建测量工具，证明灵敏度后冻结（**build-the-lever** 技能）。用对比负载确认目标案例复现症状、轻松案例按预期分离。用 **benchmark-checklist** 审查，打印错误数和工作数。冻结后一条可重复命令输出足够采样的指标。记录基线和回归关卡绿色运行。

3. 通过 **show-me-your-work** 打开决策日志。`decision.tsv` 每次尝试一行，含 id、假设、变更、前后、差值、测试、结论、说明。每次前读取，置于忽略的树外。

4. 每个假设依据架构模型写出具体机制，而非“试试 memoize”。性能指标按 `playbooks/perf-issue.md` 第 2 步口诀排序，但不借用其停止规则。

5. 每轮一个假设循环：

- 将变更交给配置的爬山模型（默认 `grok-4.7-xhigh-fast`）的子智能体，范围收紧。监督并审查差异。独立假设可扇出到各自工作树。

- 用冻结工具测量前后并运行回归关卡。

- 只有越过噪声且关卡绿色才接受，否则完整回退。“可能有用”不保留。

- 每个接受修复一次提交，只暂存你修改的文件（`git add <files>`，绝不使用 `-A`）。无论保留或回退都记录该行。
   每轮迭代在下一轮开始前检查（**sequence-verifiable-units** 原则技能）。无人值守时只借用 Autonomous run 操作手册（`playbooks/autonomous-run.md`）的唤醒机制，不借用其停止规则。

6. 越过第一个平台期。连续拒绝时换类别、组合接近方案、重读源码或尝试更激进方法。正确性和简单性高于数字。功能性胜利要回退，保持数字的简化要保留（**laziness-protocol** 技能）。

7. 谓词满足或剩余想法边际收益不足时停止。不放松谓词，不在廉价未试假设仍存时退出。卡住就上报。

8. 按接受顺序运行**创建 PR**。

**回复：** 指标和目标、基线到最终及百分比差、轮次（保留／回退）、每个接受修复一行、`decision.tsv` 路径，以及再推进会试的最佳想法。
