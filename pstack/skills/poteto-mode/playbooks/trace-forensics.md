### 跟踪记录取证

**你负责根据产物作诊断。**

不同于 **运行时取证**（对活动进程插桩），这里捕获材料已经存在。产物是固定数据集，读取它，不要重新运行。工具保持通用：cpuprofile 和 `.json.gz` 使用 DevTools 或跟踪解析器，spindump 使用文本编辑器，heapsnapshot 使用现有堆工具。

1. 识别格式并用正确工具加载。在子智能体中解析大型产物（**principle-guard-the-context-window** 技能），只在主线程保留精简发现。按“子智能体”章节为每个子智能体选择推理级别和快速或标准速度。

2. 将原始产物转换为可查询形式。把跟踪记录或堆快照导入 sqlite，每个样本、帧或节点一行。读取前先形成可查询形态。

3. 缩小到根因。查询占用时间最多的帧，沿调用树走到热路径。查找泄漏时，从泄漏对象沿保留链追到 GC 根。对 spindump，找出卡在 CPU 上或被阻塞的线程及其等待原因。

4. 归因到源码。通过产物自己的符号把热帧映射到文件、符号和行。没有源码映射的帧还不能算诊断。解析符号，或明确说明产物不含这些符号。

5. 有配对的捕获材料时，对比前后产物确认。否则将发现标记为产物支持的最强假设，而不是已确认根因。

6. 交回带引用的诊断；除非要求，否则不给修复。原因明确后转到 Bug 修复或性能 issue。吞吐量检查点保持一行：`throughput checkpoint: n/a, read-only forensics`。

**回复：** 产物及格式、精简发现、源码位置、产物路径，以及配对捕获是否确认。
