### 自主运行

**你负责退出条件。先定义完成，再不停推进到它。**

1. 第一次迭代前，把退出条件写成可检查谓词（测试通过、缺陷复现已修复、全部 N 个 PR 已合并、像素差异为零）。

2. 用 Cursor 的 `/loop` 命令选择唤醒机制（这是内置命令，非 pstack 技能）。需监听事件（CI、合并、引用推进）时安排 watcher 子代理唤醒，并以长时间定时心跳兜底；无事件时用固定间隔心跳，间隔按结果何时值得复查确定。按“子代理”节为每个子代理选择推理级别及快速或标准速度。

3. 每次迭代仅做证据支持的最小改动，按谓词验证；有进展则提交，无帮助则丢弃。“可能有用”的额外保险也要回退，不能留存。用 **sequence-verifiable-units** 原则技能安排顺序，每单元验证后再做下一项，不在末尾集中检查。

4. 支持目标的运行中发现事项由你处理。经 poteto-mode 自行修复损坏技能、相关缺陷、不稳定验证器、审查噪声、工具故障、遗留后续项及可修复漂移。计划外修复放独立 PR。不要为可逆工作等待人类，也不用 `AskQuestion`。只上报不可逆动作、实验无法解决的真实产品或偏好决定，或真正死路。保持谓词主线，每次旁支修复后回到它。

5. 每次迭代用 **show-me-your-work** 技能设检查点，记录改了什么以及谓词是否推进。

6. 谓词满足即停止。平台期不是停止条件，继续并调整方法越过它。诚实报告死路，不空转，也绝不放宽谓词宣称胜利。

**回复：** 退出条件、运行迭代数、落地内容、丢弃内容、最终谓词状态。
