### 评估

**你负责实验设计：计划、盲测、运行、综合。**

**盲测不可妥协事项：**

- 候选看到的任何目录、文件或提示词中不得出现 `eval`、`test`、`judge`、`experiment`、`rubric`、`score`、`compare`、`benchmark`、`candidate` 或 `arena`。

- 候选提示应像自然用户请求：说明目标，不暴露元信息。

- 不提供诱导链路线索；不要要求候选列出所用技能、原则或文件。只要求一般设计说明，从代码形态而非自述评分。

- 清理目录和slug名称，使用用户可能选择的项目式名称。

- 不要告诉候选还有其他候选。

- 评判者知道自己评判，但只能看清理后的标签，不看模型名。

- 比较两个变体时，同一评判者在一次评分中用同一尺度评两组，不知道每组来源。

**步骤：**

1. **界定。**说明测试的变体和成功行为；只为评判者写评分标准（3–6条具体标准），候选不可见。

2. **建立清理后的环境。**每个候选用独立工作目录并放入变体；植入自然任务会有的上下文：项目骨架和候选会自然阅读的技能。

3. **编写一条自然提示。**像用户会输入的内容，不泄露测量目标。

4. **按 arena 技能的 Phase B 派生 N 个并行候选**，分布在不同模型上；每个有自己的清理目录，提示相同。按 Subagents 部分选择推理级别与速度。

5. **按 arena 的 Phase C 派生一个盲评判者**，放在不同模型族；只给清理标签和评分标准，不给模型名。

6. **从转录验证链路，而非自述。**读取当前工作区`agent-transcripts/`中每个候选转录；不得跨`~/.cursor/projects/*/`。查看候选实际打开的文件，用真实读取文件和代码形态评分，绝不依据候选声称。

7. **亲自从头到尾阅读每个输出**，与评判结论比较。分歧表示模型偏差或标准含糊，然后综合。

**回复：**测试变体、评分标准、每候选记录、评判结论、你的综合，以及是否推广该变体的建议。
