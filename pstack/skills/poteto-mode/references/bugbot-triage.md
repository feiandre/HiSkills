# Bugbot 分诊

当 Babysit 行动手册（`../playbooks/babysit.md`）处理 Bugbot 或审查自动化评论时使用本参考。目标不是默认忽略 Bugbot，而是停止把每条评论都视作必需的代码改动。

## 决策准则

行动前对每个 Bugbot 线程分类：

- `fix`：评论指出可能的正确性、安全、隐私、数据丢失、认证、计费、迁移、幂等性、竞态或已发布行为问题。在最低层拥有该问题的 PR 中修复，然后回复提交 SHA 并解决线程。

- `dismiss`：评论符合已记录的低风险噪声模式，当前代码/上下文证明该顾虑无需代码改动。简短说明原因并解决线程。

- `ask`：评论新颖、严重、涉及安全/隐私/数据，或含义不清。询问用户，不要猜测。

拿不准时就询问。跳过一条噪声代码质量评论成本很低；跳过真实的数据或安全缺陷则不然。

## 经验模式格式

按以下形式添加未来模式：

```markdown
### <short pattern name>（简短模式名称）

- 置信度：candidate | recurring | strong
- 跳过条件：<conditions that must be true>（必须成立的条件）
- 不可跳过的情况：<risk boundaries>（风险边界）
- 示例信号：<phrases or code context that identify the pattern>（识别该模式的短语或代码上下文）
- 来源：<PR/comment URL or short historical note>（PR/评论 URL 或简短历史说明）
```

一到两个例子使用 `candidate`。在多次真实驳回后使用 `recurring`。只有模式狭窄、反复验证且低风险时才使用 `strong`。

## 反复出现的可跳过候选

### 有意进行的 UI 或设计系统视觉改动

- 置信度：candidate

- 跳过条件：PR 描述、截图、设计审查或附近代码明确说明视觉改动，且 Bugbot 评论只是在重申某个共享视觉默认值发生变化。

- 不可跳过的情况：评论指出无障碍、焦点可见性、键盘导航、颜色对比度或 PR 并未有意改变的组件 API 契约。

- 示例信号：关于焦点轮廓、按钮尺寸、间距或共享组件视觉默认值的评论，维护者回复“intentional”或“intended”。

### 上层堆叠或堆叠局部用法，Bugbot 看不到

- 置信度：candidate

- 跳过条件：Bugbot 将某个导出、组件、辅助函数或文件标为未使用，而当前代码托管平台的 PR 列表和差异、上层堆叠差异或 PR 上下文显示它由堆叠中后续 PR 使用。

- 不可跳过的情况：当前 PR 不属于堆叠，符号是公开 API，或所谓上层用法无法验证。

- 示例信号：“Exported component is never used”（导出的组件从未使用），并有类似“used upstack”（上层使用）的人类回复。

### 并行实现期间的临时重复

- 置信度：candidate

- 跳过条件：PR 有意重复少量代码，使新路径与正被删除、替换或验证的旧路径并行。

- 不可跳过的情况：重复代码改变安全、计费、数据访问或 API 行为，或长期共享抽象显然会降低风险。

- 示例信号：“Significant duplication”（大量重复）或“duplicated validation logic”（重复验证逻辑），维护者解释旧路径将删除，或重复逻辑有意局限在本地。

### 现有框架或组件不变量已覆盖警告

- 置信度：candidate

- 跳过条件：共享组件、框架契约、类型不变量或当前差异/附近代码中可见的单一事实来源已经保证该顾虑。

- 不可跳过的情况：不变量只是假定而未执行、依赖时序，或跨越异步/状态边界且值可能分叉。

- 示例信号：评论指出内部 popover 缺少 max-height，但共享 popover 强制执行视口边界；或可空值中，本地检查值和传入值来自同一来源。

### 维护者声明的后续事项或延后清理

- 置信度：candidate

- 跳过条件：PR 维护者明确表示该问题是已知后续事项，当前 PR 未使行为更糟，且评论不涉及高风险区域。

- 不可跳过的情况：代理没有维护者意见就行动，问题属于中/高严重产品行为，或延后处理会合入新的回归。

- 示例信号：“I'll worry about that later”（我稍后再处理）或“we'll delete this eventually”（我们最终会删除它）。

### 自动撤回或明确说明为误报的规则评论

- 置信度：recurring

- 跳过条件：评论正文或后续 Bugbot 回复明确表示发现已撤回、符合要求或为误报，且代理能在本地验证相关规则。

- 不可跳过的情况：唯一证据是某人在高风险问题上说“误报”而未解释。

- 示例信号：文件名规则评论正文说文件已经符合规则。

## 默认询问

即使先前 PR 曾驳回类似内容，也不要自动跳过这些类别：

- 安全、隐私、认证、计费、数据保留、训练数据及权限边界发现。

- 高严重度发现。

- 迁移、schema、幂等性、并发及跨系统行为发现。

- 建议修复很小、显然降低风险且不改变产品意图的评论。

历史数据表明人类有时会驳回安全/数据流评论。将其视为维护者的判断，而非全队跳过规则。

## 近期看护中的候选经验

看护期间或之后，若候选经验看起来对团队有用但尚未成熟，追加到这里。多项 PR 确认模式后，优先将反复出现的候选提升到上一部分。

### 手动重新实现原生浏览器行为

- 置信度：candidate

- 跳过条件：几乎从不。差异将原生浏览器行为替换为手动等价物时（原生 sticky → JS 定位克隆、原生滚动目标 → 转发 wheel/touch 事件、paint-order 遮挡 → mask/clip-path），Bugbot 针对该代码提出的逻辑缺陷一直合理。

- 不可跳过的情况：发现涉及此类代码中的事件转发缺口（wheel deltaMode、触摸平移、边缘滚动链、点击容差）、mask/clip 命中测试差异或 observer 与 React 状态时序竞态。默认修复。

- 示例信号：“masks do not affect hit-testing”“overlay blocks wheel scroll”“ignores deltaMode”“runs in the IntersectionObserver callback before React applies state”。

- 来源：一个 sticky 遮挡 PR：六轮 Bugbot，约十八条发现，全部修复而非驳回。

### 契约测试漂移主张可低成本验证——先运行测试

- 置信度：candidate

- 跳过条件：绝不跳过验证本身；只需一条命令。当 PR 包含固定协议或文档正文的契约测试（对 SKILL.md 的正则、文档措辞快照），而 Bugbot 声称“测试已不再匹配文档”（或相反），分类前在 PR 顶端运行该测试。红色运行以实证确认主张；绿色运行是驳回回复的确凿反证。

- 不可跳过的情况：不适用——这是验证捷径，不是驳回模式。注意重复通过时的“倾向驳回”启发式会在这里误判：固定正文的测试漂移，恰恰因为早先修复轮次编辑了正文。

- 示例信号：某 PR 早期修复提交改写了固定段落，评论称“Contract test omits the pre-fix wait”（契约测试遗漏修复前等待），而在顶端运行的测试正好在所指断言上失败。

- 来源：一个固定正文的 PR，共八轮 Bugbot；第 7 轮的主张是真实的，尽管此前每轮都已修复并解决。

### 过期的安全审查发现已在同一 PR 后续修复

- 置信度：candidate

- 跳过条件：代理式安全审查（或类似工具）声称缺少 authz/验证调用，而当前 PR 顶端明显包含该确切门槛（含测试），通常是在审查运行后添加的加固提交。

- 不可跳过的情况：所引辅助函数对讨论中的主体不执行操作，检查在其保护副作用之后运行，或缺少声称主体的覆盖。

- 示例信号：一条 HIGH“缺少授权检查”，而顶端在副作用前已调用确切守卫。

- 来源：一个 webhook 端点 PR，其加固提交晚于审查运行。

### 放宽有意狭窄的错误条件会掩盖真实错误

- 置信度：candidate

- 跳过条件：发现要求将狭窄错误条件（特定 `errno`、错误码或状态类别）扩大为捕获一切，而这种狭窄表达了真实区别。典型形式是以 `ENOENT` 为条件选择依赖回退：“二进制未安装”与“命令已运行但失败”是不同情形。任何非零退出都重试，会让合法失败（未找到、认证过期、网络）进入回退，然后报告回退错误，掩盖真实错误。

- 不可跳过的情况：狭窄条件遗漏同一类别中的情形（其他“二进制不可用”`errno` 如 `EACCES`、其他传输层失败）、未处理路径会丢数据或留下部分状态，或重试幂等且原始错误仍被呈现。

- 示例信号：“only retries when X fails with ENOENT … never tries the fallback even when a working Y exists”（仅当 X 因 ENOENT 失败时重试……即使存在可用的 Y 也从不尝试回退），而代码回退针对缺失依赖，不是失败操作。

- 来源：一个 CLI 重命名 PR，其回退针对缺失二进制，而不是失败命令。
