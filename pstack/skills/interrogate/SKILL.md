# 质询

对抗者尝试破坏一项变更或设计。只有通过运行证明的发现才能保留。报告发现，不要实施修复。

## 界定范围

范围是用户指明的内容。否则，范围是分支与基础分支的合并基点到工作树之间的差异。根据用户消息、提交和 PR 描述，使用 **in-your-own-words** 技能陈述意图。意图不清晰时，询问用户。

## 扇出

执行 **arena** 技能阶段 A 的步骤 3 和 4，以及阶段 B，并作四项调整。读取 `interrogate reviewers` 行，取代 `arena runners`。将范围内未提交的修改复制到每个 worktree。每个对抗者都以 `generalPurpose` 生成。用范围、意图和以下任务说明，取代 arena 任务及理由：

> 破坏这项变更。通过针对真实代码的一次运行证明每个发现，例如失败测试、复现脚本，或显示错误行为的命令输出。对于设计或计划，运行原型，或探测当前树。将复现保存在你自己的 worktree 中。报告每个发现时附上标题、确切命令、命令打印的输出，以及意图所要求的输出。没有运行过的内容一律省略。这也包括风格、命名、结构，以及只有未来修改才会使其产生影响的风险。没有发现也是有效结果。

## 验证

按照 arena 阶段 F，重新运行每个发现的命令来验证它。只有当输出展示了失败，且该失败违反意图时，才保留该发现。丢弃其余发现。合并具有相同根因的发现。

跳过 arena 阶段 C、D 和 E。对抗者寻找不同的失败，因此裁决保留每一个经过验证的发现，而不是只保留某一个对抗者的列表。

## 输出

- **意图**：重述的意图。

- **发现**：对于每个经过验证的发现，列出命令、输出、它如何违反意图，以及发现它的对抗者。如果没有发现保留下来，说明“没有经过验证的发现”。

- **已丢弃**：对于每个对抗者，列出被丢弃发现的数量和原因。
