# 纠正

操作者总在这个仓库里纠正代理的同样错误。修改仓库，让下一个代理无法再犯。

假定每个贡献者都是一个代理，只能看到自己打开的文件，会复制最近的例子，并选择能够编译的最短路径。设计仓库时，要让从单个文件看起来正确的修改，对整个仓库也是正确的。

## 找出错误类别

首先，阅读近期提交、回滚、审查评论、代理指令文件，以及解释变通方案的注释。将错误分组归类。同一类错误发生两次后才算一个类别。

## 在有效的最高层级修复每个类别

1. **通过架构消除。** 让每份状态只有一个所有者，让每项任务只有一种受支持的做法。隐藏内部实现，让错误导入直接失败。用唯一事实来源替换手动同步的列表。删除代理可能复制的旧做法和死代码。

2. **通过类型强制执行，让错误状态无法写出。** 如果错误代码仍能编译，就添加 lint 或 CI 检查，其错误消息必须指出应该改用的文件、类型或函数。如果这种模式已经很常见，只在修改进一步增加它时失败。

3. **测试行为。** 修复或删除这样的测试：所检查的行为损坏时仍然通过，或者仅内部实现改变时却失败。

4. **最后才写文档或代理规则，且仅用于需要判断的事项。** 代理跳过它们时，不会有任何检查失败。

## 修复并证明

接下来，立即修复最常见的类别，每个类别一个提交。证明每项新检查对真实的历史错误都会失败。在本地和 CI 中运行同一个命令。例外写在违规行，附上理由、到期日期和人类批准。

## 维护规则表

最后，在代理指令文件中保留一张表，把每条规则与其强制机制对应起来。当操作者纠正你时，修复错误并添加规则。如果规则已经存在，却没有任何机制强制它，这就是重复错误，因此要在同一次修改中于最高层级修复。一旦某条规则对应的错误已不可能发生，就删除该规则。

**回复：** 列出每个类别及其证据、所选择的层级，以及更高层级为什么无效。
