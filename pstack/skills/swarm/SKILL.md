# 集群

## 开始

在启动任何工作之前，打开一个待办清单，每个阶段对应一项。

1. 界定任务。

2. 扇出。

3. 汇总。

4. 报告。

## 阶段 A：界定任务

1. 说明完成判定条件，以及集群必须返回的产物或报告。

2. 选择组织形式。可以划分切片，让 N 个工作者按相同任务说明竞赛，或两者混合。对于竞赛或混合形式，在生成工作者之前声明采用 `first pass`、`rank all` 或 `best-of`。

3. 从 `~/.cursor/rules/pstack-models.mdc` 中的 `swarm workers` 行选择工作者模型。如果规则或该行不存在，使用 `grok-4.7-xhigh-fast`。对于 `auto` 或 `inherit-parent`，省略 `model`，使工作者使用父模型。如果 Task 工具拒绝某个 slug，使用默认值并说明。如果它也拒绝默认值，从其错误消息中选择同一家族最接近的有效 slug。对于模型竞赛，预先指明每个分支的模型。根据 **poteto-mode** 技能的 Subagents 章节，为每个子代理选择适合任务的推理级别，以及快速或标准速度。

4. 工作者需要写入时，为每个工作者分配自己的可写输出。当工作者验证或测量提交时，每份任务说明都要列出确切 SHA。测量任务说明还要指明方法（样本数、一个样本是什么、顺序）。工作者在结果中记录这两者。

## 阶段 B：扇出

在同一条消息中生成全部 N 个工作者，设置 `subagent_type: generalPurpose`、`environment: "cloud"`、`run_in_background: true`，并使用步骤 3 的模型；对于 `auto` 或 `inherit-parent`，不设置模型。只有工作者需要访问用户电脑上的某些内容时，才使用 `environment: "local"`。

当工作者必须从一个已推送的非默认分支开始时，传入 `cloud_base_branch`。

每份任务说明都必须独立完整。包括目标、范围、确切切片或竞赛分支、如何验证，以及报告什么。报告使用 `PASS`、`ISSUES` 或 `BLOCKED`，并附证据。能够证明缺陷的工作者报告 `ISSUES`，列出所有它能证明的问题，而不只是第一个。

如果某个工作者退出，使用 N-1 个继续推进，并注明。

## 阶段 C：汇总

阅读最终结果。若结果没有记录其任务说明要求的 SHA 和方法，丢弃该结果，并重新生成该工作者一次。第二次仍缺失时，记录一个缺口。缺口不算通过。对于覆盖任务，每个必需切片都要有结果。对于竞赛，应用预先声明的选择规则。使用 first pass、rank all 或 best-of。不要直接粘贴工作者的原始输出堆。

## 阶段 D：报告

在聊天中返回一份整合报告，包含结果表、每个问题的一行说明、缺口或退出情况，以及使用过的竞赛规则。
