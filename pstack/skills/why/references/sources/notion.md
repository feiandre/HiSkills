# Notion 文档

## 此来源包含什么

- PRD（产品需求文档）

- 技术规格与 RFC

- 架构决策记录（ADR）

- 设计评审会议记录

- 含领域上下文的团队页面

- 事故复盘

- 可能解释防御性代码的运维手册

- 设定优先级的战略文档

Notion 常在代码出现前以长文保存“为什么”。重要功能通常有文档。

## 如何搜索

使用 Notion MCP。

1. **用 `notion-search` 按关键词搜索。** 尝试：

- 功能名称

- 目标代码的关键符号/类名

- 作者账号（设计文档常在代码落地前编写）

- 错误字符串或用户可见术语

- 知道发布时间时限定时间范围

2. **用 `notion-fetch` 获取候选页。** 阅读全文，而非预览；理由常在文档中部。

3. **沿反向链接和子页面查找。** 设计文档常有已考虑替代方案、附录或实现笔记子页。

4. **检查相关数据库。** `notion-query-data-sources` 与 `notion-query-meeting-notes` 可找出讨论该决策的会议记录。

5. **搜索作者个人空间。** PR 作者若有个人笔记本（某些公司常见），其中可能有代码前的探索思考。

## 什么样的证据好

- 带“问题陈述”或“动机”的 PRD，内容符合目标代码用途

- “已考虑替代方案”或“被拒方案”部分

- 指出目标代码是某事故修复的复盘

- 记录“我们因 Y 决定 X”的会议纪要，作者/日期范围与 PR 对应

- 认真填写的 ADR（状态、上下文、决策、后果）

## 常见陷阱

- **过时文档。** 规格常在实现前写且不再更新，可能描述已变化的计划；与实际 PR 交叉核对。

- **文档与现实漂移。** 规格写“将做 X”，代码实际做 Y；标出差异供综合者指出矛盾。

- **模板套话。** 组织要求的“为什么”可能充满空话，找具体内容。

- **无链接文档。** 最相关文档可能无人链接，用宽泛关键词搜索。

- **多份草稿。** 找最终版或最新更新版，核对日期。

- **访问受限页。** 无法访问时明确记为缺口。

## 返回什么

对每份相关文档：

- 标题和 URL

- 作者与最后更新日期

- 动机原文（逐字引用）及页面/章节位置

- 相关链接页面（供综合者引用）

- 文档是最终版还是草稿
