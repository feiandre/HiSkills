# 维护验证技能

应用一变化，功能映射就开始过时。本技能是由 `/create-verification-skill` 生成的技能，或任何带功能映射的项目本地验证技能的维护循环。严谨性的单位是功能，不是每个句子：从源码覆盖每个功能文件，并实际操作每项功能，而非把每个项目符号都变成终端命令。

## 结果

选择一项，并说明是哪项：

- **clean**：每个功能都有源码及实时覆盖；没有值得交付的修改。不建分支，不开 PR。

- **changed**：一个 PR 交付已证明的文档、测试工具或映射更正。

- **blocked**：覆盖无法完成，或已证明的修复无法安全交付。准确说明阻碍。

## 编辑范围

仅编辑验证技能自己的目录，包括其 SKILL.md、features/ 及其拥有的测试脚本。运行中绝不编辑产品代码：映射描述但应用已不再具备的行为，要么是文档偏离（修正映射），要么是产品回归（报告，不在文档里掩盖）。

## 检查流程

0. **定位目标。** 找到要维护的验证技能：正文具有启动和操作章节、并带功能映射的项目本地技能，通常在 `.cursor/skills/verify-*/`。多个候选则询问选哪一个；没有则停止，并指向 `/create-verification-skill`，不要编造目标。

1. **清理索引。** 阅读功能映射 README，并用 glob 列出同级文件。修复缺失、多余、重复或失效条目。保持轻量，不生成清单。

2. **源码并行检查。** 每个功能文件分配一个只读子代理，并发启动。各自从源码解释“这个面向用户的功能如何工作？”，用引用标出疑似文档偏离，并返回一份简洁的实时验证方法。子代理绝不操作应用，也绝不编辑文件。返回形式：功能概况 / 源码入口 / 疑似偏离或无 / 一份验证方法。

3. **协调结果。** 每个功能文件都有返回概况。将重叠方法合并为尽可能少的应用状态。抽查引用的偏离，不重新证明无问题声称。扫描近期频繁变化，查找映射遗漏的用户可见功能；认定遗漏前必须有具体源码路径。

4. **实时检查。** 即使源码看起来无问题，也必须执行。协调者负责所有操作；遵循验证技能自身的启动模型：服务器和 UI 使用一个长生命周期实例串行操作；短生命周期 CLI 则每次操作使用新的隔离会话，具体由该技能的 Launch 章节决定，不由这里决定。每个功能至少操作一次，并在整个检查中无论发生什么失败都维持三个不变量：(1) 绝不操作自上次异常后未做健康检查的实例。首次操作前运行 doctor；以会话为单位时，每个新会话运行 doctor；每次操作失败后再运行 doctor；如果 doctor 看不到失败，例如进程正常但 UI 卡住，就重置到已知状态或重启，不要抱侥幸。(2) 已捕获的证据必须在每次清理后仍保留，并在其指定位置检查，而非假定存在。(3) 某次操作启动的任何东西，都不得活得比其有用时间更长。无论会话卡住、退出还是共享，都清理失败迭代的残留；共享实例清理残留，而非实例本身。由技能偏离导致的 doctor 失败属于偏离：在编辑范围内修复并重试一次，只重启该修复使之失效的部分，不做更多，然后才可将检查标为 `blocked`。只有给出具体前置条件（认证、权限资格、操作系统、外部状态）及已尝试路径，才可把无法到达的功能标为 `verified-unreachable`；如果映射遗漏该前提，这就是偏离。分诊产生的任何测试工具修复在交付前都要重新实时操作。最终清理发生在本次运行最后一次操作之后，包括这些重新证明的操作，确保没有东西比运行本身活得更久；证据按技能规定保留。

5. **分诊。** 用户视角描述错误或缺失，属于文档偏离，修正文档。行为正常但测试工具无法操作，属于工具缺口，修复它；工具修复遵循生成时同样的辅助脚本规则，脚本可执行，调用方法在技能正文中记录。应用行为本身出错，属于产品缺口；记录给用户，不放入此 PR。

6. **交付或停止。** 对 changed：用一个 PR 交付已证明的更正，先重读每个改动文件。对 clean 或 blocked：不开 PR，如实报告结果与覆盖。

在临时位置保留简洁运行笔记，包括已覆盖功能、不可达的前置条件、已确认偏离及结果；不要提交。
