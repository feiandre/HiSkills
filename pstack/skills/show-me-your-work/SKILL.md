# 展示你的工作

保留一份权威日志。

## 格式

单个 TSV 文件，每个决策一行。单元格保持单行。证据是指针，不是正文。

复制 `references/decision-log-template.tsv`（标题行）以开始干净日志。列：

- **ts。**ISO8601 时间戳。

- **phase。**阶段或工作流。

- **decision。**选择或完成了什么，一行。

- **why。**平实原因。若由某项原则驱动，直接说明，而非用术语标签。

- **evidence。**证明它的链接或路径：提交 SHA、PR 编号、`file:line`，或制品、跟踪、截图路径。绝不是段落。

- **result。**结果或谓词状态：`tests green`（测试通过）、`reverted`（已还原）、`pixel-diff 0`（像素差为 0）、`INCONCLUSIVE`（不确定）、`open`（开放）。

示例，采用平实语言，让审查者一眼读懂。

```
ts	phase	decision	why	evidence	result
2026-05-24T09:02:00Z	frame	先统计工作量，大约 100 个组件和 75 小时	开始长时间运行前想知道规模	commit 3a9f1c2	发现开始前有 5 件事要处理
2026-05-24T09:40:00Z	harness	改动前先给旧版本截图	这样可比较新旧并捕获任何视觉变化	scripts/snapshot.sh, baseline/	保存了 120 张参考截图
2026-05-24T11:15:00Z	widget	迁移组件样式而不改变外观	保持改动小且结果一致	commit 7c21e0a, pixel-diff 0	外观一致，测试通过
2026-05-24T12:30:00Z	widget	丢弃一个辅助代理的工作，因为截图是空白的	检查真实文件而非相信其摘要	worktree reset	已还原，并收紧下次指令
```

## 记录一行

像向队友说明你做了什么那样写每条记录。平实词语、具体动作，不用 AI 腔或抽象术语（**unslop** 技能也适用于日志文本）。

使用辅助脚本 `scripts/log.sh <logfile> <phase> <decision> <why> <evidence> <result>`。它会写入 `ts`，首次使用时写标题，去掉游离制表符/换行，并为以 `=`、`+`、`-` 或 `@` 开头的单元格加单引号前缀。裸 `printf` 追加一行也可以，但单元格来自生成或用户提供文本时要注意相同字节。

记录决策点与检查点，而非每个动作：选择了一个分叉、完成一个单元及验证结果、一次转向或还原及触发因素、暴露一个阻塞、修复一个门槛。循环运行每次迭代一行。跳过琐碎和显而易见的内容。

一次运行是一个代理会话，包括其后续轮次及任何摘要。接手、替换代理或新聊天都开始新运行。某次运行向已有行的日志追加时，其第一行用阶段 `start`；在另一运行的 `start` 行后，它的第一行也用 `start`。因此稍后轮次回到日志的运行，先读取最后几行，看看是否有另一运行写过。`start` 行会命名此前不属于本运行那些行的 `ts` 范围，其证据命名本运行，例如代理 ID。阶段 `start` 不作他用。

## 存放位置

默认日志是工作制品，不提交。放在工作目录的 `decisions.tsv`，多个工作并行时放 `.audit/<task-slug>.tsv`，并排除在 git 外。

只有工作足够大，审查者需要轨迹来信任结果时才提交。

## 规则

- 仅追加。错误决定用新行取代。绝不编辑或删除历史。

- 优先使用已提交脚本产生的证据，而非手工一次性操作（**encode-lessons-in-structure** 原则技能）。

## 对照记录审计日志

运行结束、交付前，检查日志是否说了真话。在活动工作区的 `agent-transcripts/` 目录读取本次运行的记录（系统提示词会给出路径）。不要通配 `~/.cursor/projects/*/`，那会读取无关私聊。将本次运行的行与实际发生内容逐段核对。每段从本次运行的一个 `start` 行开始（若日志由本次运行创建，则从第一行开始），到另一运行的下一个 `start` 行结束：

- 检查每行对应真实决策或动作。

- 检查每行证据可解析，并显示该行声称的内容。

- 影响工作但未记录的分叉、转向或放弃方案是缺口。补上。

修正日志，不修正故事。审计绝不编辑或删除行，即使行是虚构的。若一行既不记录真实决策也不记录真实动作，或主张/证据有误，添加取代行，记录实际发生内容及可解析指针。此审计不检查本次运行片段之外的行。若本次运行工作表明其中一行错误，像任何错误决定一样取代它。

## 跨模型审查轨迹

交付前，生成一个与工作者模型家族不同的子代理。自审不能替代。子代理读取审计轨迹和本次运行记录，然后标出用户应关注之处。不是重做工作，而是扫描次优或风险点。按 **poteto-mode** 技能的 Subagents 部分为工作选择每个子代理的推理级别及快速/标准速度。

- 证据薄弱或缺失的已记录决策。

- 跳过验证步骤，或在记录中声称验证但无证据。

- 事后看来有风险的选择（过早、范围蔓延、掩盖症状）。

- 用户随意浏览时可能错过的缺口。

产生轨迹的每次运行回复都以“Attention”（注意事项）部分结尾。先单独一行写审查模型（`reviewed by <model>`），然后列出每个标记及具体行或时刻。“无标记”是有效值。模型名不是。

## 审查轨迹

从上到下阅读，跟随证据指针，抽查。GitHub 将已提交 TSV 渲染为表格。`column -s$'\t' -t decisions.tsv` 在终端渲染。

## 组合本技能

其他技能将审计轨迹路由到这里，而非另发明格式。按名称引用，并让它负责格式。不要重述列。
