# 回忆

**开始或恢复工作前，重建用户近期工作上下文，返回当前状况和下一步的紧凑胶囊。**

保持紧凑且切题。只读范围内线程需要的内容，然后停止。

上下文存在两份记录。你的聊天历史包含所做和决定；共享记录包含同一代码周围其他名称下的内容：用户反复报告的症状、发布后回退的修复、生产仍触发的错误。**why** 技能会搜索源码控制、issue 跟踪器、聊天频道、长文档和错误跟踪器。长 bug 尾巴的功能大部分故事在那里，不要仅从记录重建。

记录位于 `~/.cursor/projects/<slug>/agent-transcripts/<uuid>/<uuid>.jsonl`；`<slug>` 是去掉前导斜杠、把 `/` 换成 `-` 的工作区路径。每行一条消息。，相关标识为 `/Users/you/proj` `Users-you-proj`。

1. 分类后路由。恢复一个聊天用 `session-pickup`，把习惯变技能用 `automate-me`。人类可读工作总结是另一任务。回忆在行动前加载近期上下文；用户已给完整胶囊（路径、分支、变更）时直接使用并跳过挖掘。

2. 搜索前锁定范围。固定窗口（“近期”默认 7 天）、主题和工作区（默认当前；未经要求绝不读其他项目记录）。复述范围，绝不把“全部”悄悄变成“近期 N”。

3. 并行扫描聊天历史。用快速便宜模型分片；按真实修改时间（`ls -t`）排序，先 grep 主题，只读匹配和相关区域，跳过当前聊天及噪声（子智能体、评估、测试聊天）。每个返回同一结构并按聊天 UUID 引用。只有一两个聊天时直接搜索。原始记录留在子智能体，主线程只接收发现。

4. 主题涉及功能、文件、子系统、区域或 bug 时扫描共享记录，这是默认行为。交给 **why** 调查者，把问题改为当前状态、尝试过但未成立的内容、用户仍报告什么。并行运行，来源不可用记结果并说明。只有无目标纯活动回忆才跳过。

5. 用 `git` 和 `gh` 对照实时状态验证 PR、分支、票。答案取决于智能体实际动作时读完整记录。

6. 按下方契约写简报，按线程分组并保持主题。

## 输出契约

先胶囊，再线程状态、问题、下一步。更深细节靠后或删除。

- **胶囊。** 最多 5 条，整体工作是什么及状态。

- **线程。** 每行一个线程，准确带一个状态标签：`[merged #N]`、`[open PR #N]`、`[in flight <branch>]`、`[verified, uncommitted]`、`[reverted #N]`、`[planned, not started]`。

- **问题。** 最多 5 个反复问题。包含持续症状和回退修复，使下一次从失败处开始。

- **下一步。** 一个最有用、具体动作。

相邻功能或票除非阻塞本项否则排除。胶囊和线程超过一屏时先删细节。用 **unslop** 编写，聊天发现按 UUID 引用，共享记录按来源引用，公开输出前净化私有上下文。

**回复：** 上述契约简报。
