# 头脑风暴重建：意图

## 为什么重建

编码代理很擅长构建，却常按自己以为人类想要的内容直接构建，很少充分询问和观察。头脑风暴技能用于弥合差距：在构建前引出真实意图，包括用户尚未想清的部分。

原 superpowers 提示约四十词就做得很好：“我脑中有个想法，请多问我问题。当你认为理解我真正想要什么时，用约 200—300 词的分块描述给我。达成共识后写一份非正式规格。” 现技能已增长到约 2,600 词，几乎全是路由（spike / bounded / architectural）、批准关卡、规格到计划交接。意图被压成一段，默认动作是“问一个聚焦目的的问题”，对人不起作用。

这是从头重写，不是编辑。

## 目标

- 代理理解任何非平凡事项背后的*为什么*；知道原因才能做好一百个未言明决定。

- 人类最终想清真正想要什么；好问题帮助充实未完成想法。

- 适用于任何领域：软件、演讲、装修、小生意。

- 最终文档让该领域有能力的构建者无需再问人类即可制定计划。

## 会话应有的感觉

**先私下检查。** 代理问自己：我对他们想要什么及为何知道多少？若“几乎所有”（“把图标改矢车菊蓝”），确认后完成；缺非平凡信息则开始提问。

**一次一问。** 默认平实语言，难度略高于人类。问题应帮助思考，不是考试。

- 先让他们描述；开放问题优于菜单，菜单会把人类引向代理假设。

- 只有卡住时才提供菜单。

- 说“你猜”“你怎么看”时，始终提出建议。

- 用真实时刻（“说说上次……”）和具体取舍（“如果只能做好其中一个……”）落地问题。

- 问先例与现状：别处有什么、现在有什么。

- 问哪些*做法*想自己决定，哪些交给构建者。

需大致覆盖：事物类型、特殊之处、目标、非目标、反目标、在意细节、想委派什么。这些是范围而非脚本，绝不逐条朗读。

**提议侦察。** 有些基础后，可提出查看代码库/项目、人类文件数据或网络；由人类决定。

**具体后展示。** 图示、模型、一次性原型适用可视化伴侣，看图优于文字。

**用 spike 摸底。** 代理式开发是瀑布式但极快；快速一次性构建常最便宜。人类只想 spike 时不阻碍。spike 无或极少测试、不追求无懈可击、不走完整计划实施审查，所得重新进入对话。

**内部广泛思考。** 提议前生成多个想法、丢弃弱项；只有比较有助于决定时才展示。

**复述。** 认为理解后，以约 200—300 词分块描述，每块后调整。

## 产出什么

一份平实书面文档，覆盖：

- 意图与原因

- 目标、非目标、反目标

- 约束

- 人类在意并已决定的*做法*部分

- 明确留给构建者的内容

**完成测试：** 人类审阅前，由全新子代理扮演领域内优秀构建者，阅读并列出仍需询问的问题；问题交回人类。构建者无重要问题可问时完成。

**判定工作规模。** 意图清楚后分三类并说明，人类可覆盖：

- **快速清晰任务**：开始就清楚，确认后做。

- **小改动**：完整描述在聊天中，无文档。

- **有书面设计的项目**：上述文档加完整计划（软件用 writing-plans 技能）。

这取代旧 spike / bounded / architectural 选择：发生在意图之后，用直白名称。

**批准。** 无论规模，构建前批准完整描述：小改动在聊天批准，项目阅读文档批准。

**退出。** 会话早期说明一次：不想走流程可直接说。

## 非目标

- 设计人类未要求决定的架构；文档只记其在意的做法，其余归构建者。

- 不专用于软件。

- 不为琐碎请求增加仪式。

## 反目标

- 审讯：把问题清单机械投向人类。

- 花园路径：用引导菜单把人带向代理偏好。

- “你到底想做什么？”式提问，把代理思考推给人类。

- 小请求膨胀成多阶段项目。

- 人类同意复述前开始构建。

## 决定

- 名称保留 `brainstorming`，其他技能与 README 引用它。

- 可视化伴侣及服务器脚本保持。

- `spec-document-reviewer-prompt.md` 改为构建者检查提示。

- 代理先筛选构建者问题：能从上下文回答的回答，委派细节问题删除；无子代理工具则自行检查。

- 保留简短硬关卡：批准完整描述前不构建。例外：人类同意 spike，仍标一次性；保留产物是新请求，须过关卡。

- 构建者检查只针对书面文档，小改动留聊天。

- 触发描述保留强措辞“在任何创造性工作前使用”；开场检查让琐碎请求保持轻量。

- 删除旧待办示例；旧路由评估 `brainstorming-todo-purpose-discovery`、`brainstorming-todo-shared-intent` 同步改写。

- 软件项目文档默认仍在 `docs/superpowers/specs/YYYY-MM-DD-<topic>-design.md`。

## 留给构建者

- 技能章节结构和措辞。

- 构建者检查的确切提示。

- 非软件文档保存位置（无人类偏好时）。
