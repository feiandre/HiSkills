# 技能指导的正向指令重设计——设计规格

**状态：** 提议（2026-06-09 SDD 审查派发工作的后续；按“一个 PR 一个问题”规则单独提交 PR）  
**驱动因素：** 2026-06-10 的测量证据表明，技能文字中的某些否定指令适得其反，另一些有效，而且差别可预测。

## 本规格概括的实测发现

2026-06-10 的微型测试（opus，每种措辞 5 次重复，程序化评分；运行环境见下）测量指导措辞如何改变控制器组成：

| 案例 | 措辞 | 结果 |
|---|---|---|
| 派发组成（“不要重述简报”） | 禁止式 | 重新输入 **4.4** 个规格值——*比无指导更差*（3.6） |
| 派发组成 | 正向配方（“你的派发应包含：(1)…(5)”） | **3.0，零方差**——采用 |
| 派发组成 | 配方＋细微例外（“只引用片段……”） | 3.8，噪声大——细微例外稀释配方 |
| 测试重跑指令（“不要要求审查员重跑测试”） | 禁止式 | **0/5 违规**——有效（对照 3/5） |
| 测试重跑指令 | 正向配方 | 0/5——相同但更长 |

**规则**（用此分类任何否定指令）：

1. **绊线有效。** 对具体 token 的短语级自查（“如果你写的提示包含‘不要标记’……停下”）可靠触发。

2. **识别表有效。** 警示信号／合理化表在决策时读取，不在组成输出时读取。

3. **离散指令式禁止有效。** 模型没有做 Y 的竞争激励时，“不要要求 X 做 Y”成立。

4. **组成型禁止适得其反。** 模型对输出有自己的议程（例如重述规格感觉像有帮助的整理）时，只有正向组成配方能改变行为；给获胜配方添加细微例外反而更糟。

5. **打平时选较短措辞。** 长会话中 Codex 约重读 SKILL.md 500 次（2026-06-10 测量），文字长度是实际成本。

## writing-plans 变更（延后项 #5）

### 当前状态

`skills/writing-plans/SKILL.md` 的“No Placeholders”：一句正向话（“每一步都必须包含工程师需要的实际内容”）后跟六条禁用模式（“绝不要写：‘TBD’、‘TODO’、‘添加适当错误处理’、‘为上述内容写测试’、‘与任务 N 类似’……”）。

### 为何重要且确实不确定

- 计划是工作流中**最大的生成产物**，模型有真实竞争激励输出占位符（长度压力下最省力）——属于禁止可测量地适得其反的激励结构。

- 但禁用项是**离散、可识别 token**——属于禁止被测量证明有效的结构。

- **列表在别处承重：**技能自查章节引用它（“占位符扫描：搜索计划中的警示信号——上述‘No Placeholders’章节的任何模式”）。这些 token 兼作审查时扫描清单，审查时识别属于有效类别。直接换成正向清单会破坏引用并丢弃有效的绊线 token。

### 待测试变体

- **V0（当前）：** 正向句＋组成时禁用列表；自查引用列表。

- **V1（审计清单）：** 组成时仅正向配方——“完成步骤前确认包含：要写的实际代码、含预期输出的可运行命令、本计划中定义的类型和方法名、明确展示的错误处理。工程师不必追问即可实现时，步骤才算完成。”自查保留通用占位符扫描。

- **V2（按机制重组——预测赢家）：** 组成时只保留 V1 正向配方；具名模式整体移入自查占位符扫描，改为识别（“扫描时查找：‘TBD’、‘TODO’、‘与任务 N 类似’……”）。相同 token，从诱发组成阶段移到检测阶段。

- **V3（对照）：** 只有正向句，任何地方都无列表。

### 微型测试设计

- **任务：** opus 根据刻意欠规格的规格编写 2-3 任务实现计划（欠规格会诱发占位符）。夹具规格含：一个清楚任务、一个错误处理含糊的任务、一个与第一个相似的任务（诱发“与任务 1 类似”）。

- **采样：** 每变体 5+ 次，默认温度，模型 `claude-opus-4-8`（实际写计划的模型）。

- **程序化评分**（除注明外越低越好）：

- 禁用 token 数：`TBD|TODO|implement later|fill in details|appropriate error handling|handle edge cases|Similar to Task|Write tests for the above`

- 修改代码但缺少围栏代码块的步骤

- 引用计划输出中未定义的类型／函数

- （越高越好）每个任务含预期输出的可运行命令

- **V2 两阶段评分：** 也测试自查部分，将生成计划连同该变体自查章节送回，测量扫描是否抓到植入占位符（夹具计划插入 2 个已知占位符；检测率为指标）。

- **验收：** 只有变体在禁用 token 数上优于 V0 且不损失代码块覆盖或自查检测率时才采用。预计总成本约 6 至 10 美元。

单独 PR（writing-plans 是另一个技能；其“No Placeholders”是调优内容，贡献指南要求评估证据）。PR 必须包含微型测试工具及结果表、前后文字和 V2 重定位理由。

## 结果：writing-plans 微型测试（2026-06-10 本规格写完后运行）

**已解决——无需变更。** 阶段 1（3 任务规格，无压力）：4 个变体共 20 份计划均无占位符，包括无指导对照。阶段 1b（10 任务规格、五个近相同命令诱发“与任务 N 类似”、明确约 2500 词经济目标）：40/40 干净——唯一 regex 命中是 V2 自查*证明*“无 TBD/TODO ✓”。当前代 opus 即使在刻意压力下、无论有无禁用列表，都不产生计划占位符。处置：No Placeholders 章节保持原样（成本低且反事实无法测量）；**不要**创建后续 PR。若未来模型代出现回退，V2 重定位设计仍存此文件。

## 明确未丢弃的事项（已测试但否决，附数据）

记录下来避免无新证据重提——完整数字见 2026-06-09 SDD 设计规格成本迭代章节：

- **控制器轮次批处理／单消息并行工具调用：** 控制器每条消息恰好一次工具调用（所有运行，无论有无指导，均为 0 条多工具消息）。46% 轮次是思考／叙述且无工具调用，形成提示无法降低的下限。

- **通过并行调用流水化审查：** 因同样原因不可行。

- **通过 `run_in_background` 流水化审查：** 提供时采用该机制（7/28 次派发），但收益低于 45 分钟场景运行间噪声底（每次审查仅约 30-60 秒），还增加双结果流协调。只有计划中单次审查很长时才值得重看。

- **给获胜配方追加细微例外：** 可测量地降低效果（C2：3.8 噪声 vs C：3.0 稳定）。应重新推导配方，而不是追加注意事项。
