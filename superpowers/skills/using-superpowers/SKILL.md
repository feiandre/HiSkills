</EXTREMELY-IMPORTANT>

## 规则

**在任何回复或行动之前，调用相关或被请求的技能**——包括提出澄清问题、探索代码库或检查文件。如果调用后发现不适合当前情形，就不必继续使用。

**进入计划模式之前：** 如果尚未进行头脑风暴，先调用 brainstorming 技能。

然后声明“使用 [skill] 来 [purpose]”，并严格遵循该技能。如果它有检查清单，为每项建立一个待办。

## 技能优先级

多个技能同时适用时，流程技能优先——它们决定方法，然后由实施技能（frontend-design 等）执行。Brainstorming 和 systematic-debugging 是 Superpowers 最常见的流程技能，但此规则适用于所有流程技能。

- “我们来构建 X” → 先 `superpowers:brainstorming`，再使用实施技能。

- “修复这个缺陷” → 先 `superpowers:systematic-debugging`，再使用领域技能。

## 危险信号

出现这些想法就意味着要停止——你正在自我辩解：

| 想法 | 实际情况 |
|---------|---------|
| “这只是一个简单问题” | 问题也是任务。检查是否有适用技能。 |
| “我需要先了解更多上下文” | 技能检查必须在澄清问题之前。 |
| “让我先探索代码库” | 技能会告诉你如何探索。先检查。 |
| “我可以快速检查 git/文件” | 文件没有对话上下文。检查技能。 |
| “让我先收集信息” | 技能会告诉你如何收集信息。 |
| “这不需要正式技能” | 如果技能存在，就使用它。 |
| “我记得这个技能” | 技能会演进。阅读当前版本。 |
| “这不算任务” | 行动 = 任务。检查技能。 |
| “这个技能太小题大做了” | 简单的事情会变复杂。使用它。 |
| “我先做这一件小事” | 做任何事情之前先检查。 |
| “这样感觉很有效率” | 缺乏纪律的行动会浪费时间。技能用于防止这一点。 |
| “我知道这是什么意思” | 知道概念 ≠ 使用技能。调用它。 |
