# 诊断 Superpowers

## 概览

与人类伙伴一起确定会话中出了什么问题，阅读磁盘上的记录，并用证据报告发生了什么。你负责报告，不负责诊断 superpowers。由分诊报告包或 issue 的人决定 superpowers 是否改变。

**核心原则：**每项发现都引用 `path:line`。无引用，无发现。每个数字都来自记录或你运行的命令，绝不来自记忆。

## 工作流

每一步创建一个待办。步骤 5–7 仅在所述条件成立时运行。

1. **问题受理。**一次问一个问题，直到你能写出陈述，指明会话、已知时轮次范围、伙伴期望什么、实际发生了什么，以及关心的可观察量（实际耗时、token、重复动作、某个具体动作）。“耗时太久”是抱怨，不是问题陈述。记录目标是否为 superpowers 缺陷报告。

2. **定位。**按 `references/session-discovery.md` 将每个会话解析为已验证的绝对文件系统路径。引用首条提示和时间戳确认过去会话，并列出每个被拒绝候选及原因，或“无”。枚举子代理记录。创建 `~/.superpowers/diagnosing-superpowers/<session-id>/`，告知伙伴路径，并在其中填写 `templates/case.md`，遵循其环境与技能观察的来源规则。

3. **分诊。**亲自阅读报告问题附近区域。然后按维度并行派发一位分析师子代理，每位获得案例文件路径、`prompts/analyst-common.md` 及 `prompts/` 中一个维度文件：`skill-timeline.md`、`plan-adherence.md`、`repeated-work.md`、`stumbles.md`、`quality-evidence.md`、`request-conflicts.md`、`cost-and-time.md`。记录很长时按轮次范围拆分维度。丢弃任何未带 `path:line` 的返回发现。

4. **报告。**按顺序填写 `templates/report.md` 每一部分，写入工作区、展示并给出路径。检查所引内容实际证明什么并保留支撑案例；符号链接别名不是冗余副本。

5. **GitHub issue**——报告 §7 说可能或很可能，或伙伴要求时。按 `references/github-issues.md` 搜索打开和已关闭 issue 中的症状。展示匹配项并建议把报告加入最接近者。若没有匹配，填写 `templates/issue.md`、写入工作区、展示确切文字，并仅在批准后创建 issue。`gh` 不能附加文件；若存在报告包，给伙伴其路径以便在浏览器附加。

6. **导出**——仅在伙伴要求报告包时；绝不在未要求时构建。若受理目标是缺陷报告，说明一次已清理报告包可按需提供，然后等待。询问脱敏级别并说明各自包含：skeleton（无工具结果正文）、evidence（仅引用事件正文）、full。按 `templates/bundle-README.md` 构建报告包，派发 `prompts/scrub.md`，再派发 `prompts/scrub-audit.md`，重复两者直到审计返回 CLEAN。展示最终清理日志、文件清单及隐私/证据结果前，完成报告包模板的证据检查与对账。仅在批准后归档（`zip -r` 或 `tar -czf`）。给出归档路径时，说明其内容、指向清理日志查看替换项，并说明清理可能遗漏：共享前必须逐个审查文件。

7. **相似会话**——被要求时。将确认发现转化为签名，按 mtime 和大小列出候选，找到标记行号，按候选并行派发 `prompts/similar-session.md`，并追加报告 §9。

## 快速参考

七位分析师始终运行。此表说明步骤 3 自己先阅读哪个区域，以及结论应首先呈现哪些发现。

| 抱怨 | 先阅读、先呈现 |
|---|---|
| “耗时太久” | cost-and-time、stumbles |
| “它为什么做额外工作？” | repeated-work、plan-adherence |
| “为什么这么贵？” | cost-and-time |
| “它到底在做什么？”（仍在运行） | skill-timeline；在覆盖中注明进行中 |
| “它忽略了计划” | plan-adherence，先看压缩行 |
| “技能 X 从未触发” | skill-timeline |

## 硬规则

- **上下文安全。**一行记录可能有一兆字节。每次处理每个会话文件都遵循 `references/context-safety.md`。

- **只读。**绝不修改、移动或删除会话文件。

- **给子代理精确路径。**子代理的“当前会话”是它自己的。传入绝对路径和 ID。

- **仅人类提示词。**钩子输出、系统提醒和工具结果不是伙伴的话。在子代理记录中，“user”是父代理。

- **不做 superpowers 诊断。**报告 §7 说明参与情况后停止。绝不说技能存在缺陷或提议改动。伙伴催促修复也不豁免；指向 issue 步骤并说明报告包可按需提供。也不要给伙伴建议。

- **批准门槛。**伙伴看到清理日志和文件清单前不得归档。对方批准确切文字前不得创建 issue 或评论，也不得用占位摘要。

- **先受理再分析。**在伙伴回答前，步骤 2–7 都不开始。若对方离开，写下问题并停止。你替其重建的陈述不是回答。已明确范围请求——某个具体事件、当前正在运行的内容，或要运行的分析——本身就是陈述：回答它，然后提问。整个会话的“为什么”是抱怨。

## 危险信号

| 想法 | 现实 |
|---------|---------|
| “问题很明显，跳过受理” | 问题陈述界定一切。要问。 |
| “他们不在，我重建陈述” | 你无法重建他们想要什么。写下问题并停止。 |
| “我先扫一遍，最后再问” | 无范围扫描把他们的预算花在错误问题上。先问。 |
| “他们要缺陷报告，所以我现在构建报告包” | 报告包是打包后的会话数据。仅在要求时构建。 |
| “小范围定向编辑，无需重构” | 无论多小都由不得你。报告证据；分诊者决定。 |
| “每 token 价格众所周知” | 未从记录计算的数字是虚构的。引用或丢弃。 |
