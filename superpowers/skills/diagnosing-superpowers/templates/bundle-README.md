将头部版本字段限定为历史证据、未验证快照、当前观察或未知。`environment.json` 对每个环境字段及其支持位置保留相同的来源区分。

## 这是什么

一份经过脱敏的编码代理会话记录：该会话安装了 superpowers，且出现了问题。它让未在场的代理或人员判断 superpowers 是否有影响；若有，应改什么。内部报告以 `path:line` 证据陈述发生的事。按设计，它不包含对 superpowers 的诊断或修复建议；那是读者的工作。

## 文件

- `report.md`——诊断报告（问题陈述、结论、环境、会话、时间线、发现、涉及情况、覆盖说明）。

- `case.md`——分析者依据的案例文件。

- `environment.json`——环境章节的机器可读副本。

- `timeline.md`——逐轮时间线。

- `findings/<dimension>.md`——每个维度的原始分析发现。

- `transcripts/<session-id>.md`——各已检查会话按轮次压缩呈现的记录（绝不使用原始 JSONL）。各级别的工具结果正文：

| 级别 | 工具结果正文 |
  |---|---|
  | skeleton | 刻意限制；替换为 `[tool result: <tool>, <bytes> bytes, exit <code>]` |
  | evidence | 保留被引用事件，包括支持发现所需的命令和结果 |
  | full | 全部保留 |

- `scrub-log.md`——使用的每个占位符及其类别（绝不包含原值）。

## 如何阅读

先看 `report.md` §1—2，再看 §7（涉及情况）及其引用的证据行，然后看 `transcripts/` 中对应轮次。`path:line` 引用指向报告者机器上的原文件；压缩记录以 `[L<n>]` 标记保留相同行号。

## 脱敏

占位符形如 `<EMAIL-1>`、`<PERSON-2>`、`<SECRET-3>`、`<HOST-4>`、`<REPO-5>`、`<ORG-6>`、`<PROPRIETARY-7>`；主目录路径改写为 `~/…`。同一包内，相同占位符始终指向同一原值。

## 制作者说明

完成的包以实际结果替换这些说明。

脱敏后，仅依靠此包检查每条导出的重要发现：将引用解析到包内对话记录／来源标记，阅读被引用的命令／结果或引文，验证它支持断言。路径和行号存在还不够。脱敏级别或必要保留不导出的内容使支持丢失时，记录具体限制。

使报告、案例、环境、发现、README 及本地问题草稿相互一致。根据最终文件刷新 scrub-log 计数，排除日志本身。删除陈旧导出声明；区分包准备与归档交付。保留从历史锚点到包内证据的映射。

将独立隐私审计与证据可用性分别记录：

- 隐私审计：CLEAN 或尚未解决的遗漏。

- 证据支持：有支持或受限，说明受影响的发现及原因。

检查后内容改变，就重做受影响的检查。为已有的归档批准展示最终日志、文件列表及两项结果。归档已审阅文件，并验证交付归档与它们一致。在审阅包之外记录归档交付，不要在批准后修改包内容。脱敏并非穷尽式隐私认证。
