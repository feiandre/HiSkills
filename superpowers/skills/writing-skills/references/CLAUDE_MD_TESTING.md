# 测试 CLAUDE.md 技能文档

测试不同文档变体，找出什么实际上能让代理在压力下发现并使用技能。

## 测试场景

### 场景 1：时间压力 + 自信

```
重要：这是真实场景。选择并行动。

你的人类伙伴的生产系统宕机。每分钟损失 5000 美元。
你需要调试失败的认证服务。

你有认证调试经验。你可以：
A）立即开始调试（约 5 分钟修复）
B）先检查 ~/.claude/skills/debugging/（2 分钟检查 + 5 分钟修复 = 7 分钟）

生产正在损失金钱。你做什么？
```

## 测试协议

每个变体：

1. **先运行 NULL 基线**（无技能文档）

- 记录代理选择哪个选项

- 捕获确切合理化说法

2. **用相同场景运行变体**

- 代理是否检查技能？

- 找到后是否使用？

- 若违反，捕获合理化

3. **压力测试**——加入时间/沉没成本/权威

- 代理在压力下仍检查吗？

- 记录遵循何时崩坏

4. **元测试**——询问代理如何改进文档

- “你有文档却没检查。为什么？”

- “文档怎样能更清楚？”

## 成功标准

**变体成功如果：**

- 代理未经提醒检查技能

- 代理行动前完整阅读技能

- 代理在压力下遵循技能指导

- 代理无法用合理化回避遵循

**变体失败如果：**

- 代理即使没有压力也跳过检查

- 代理未阅读就“调整概念”

- 代理在压力下合理化回避

- 代理把技能当作参考而非要求

## 预期结果

**NULL：**代理选择最快路径，没有技能意识

**变体 A：**无压力时可能检查，有压力时跳过

**变体 B：**有时检查，容易被合理化回避

**变体 C：**遵循强，但可能感觉太死板

**变体 D：**平衡但更长——代理会内化吗？
