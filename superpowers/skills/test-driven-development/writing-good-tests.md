# 编写优秀测试

**编写或修改测试、添加 mock，或添加测试清理／辅助方法时加载此参考。**

## 概述

测试用于捕捉特定破坏。两条原则支配本文件：

```
1. 每个测试说出它能捕捉的破坏
2. 每个测试操作真实对象
```

严格 TDD 会自然产生两者：先写测试并观察它在真实代码上失败，已经证明能失败；只有真实依赖被证明慢或外部时才使用 mock。

## 原则 1：说出它会捕捉的破坏

编写测试主体前回答：**什么生产变更应让此测试失败，那是 bug 还是决策？**测试通过捕捉错误分支、缺失副作用、错误参数、边界情况或破坏契约来证明价值。

**独立推导期望值。** 使用字面量和手工核验夹具；带字面 `want` 值的表驱动测试是首选。由被测代码或其辅助函数计算的期望无论代码做什么都会通过：

```typescript
const expected = buildSearchQuery({ tag: 'urgent' });
expect(buildSearchQuery({ tag: 'urgent' })).toBe(expected);
expect(buildSearchQuery({ tag: 'urgent' })).toBe('tag:"urgent"');
```

**不要做变更检测器。** 如果只有有意决策能让测试失败（常量值、准确消息措辞、私有结构），它会在重设计时报警，却对 bug 休眠。测试依赖该决策的行为：不是 `expect(MAX_RETRIES).toBe(5)`，而是“失败调用重试 5 次，第 6 次永不发生”。

**测试行为，不测文本。** 断言脚本、技能或配置包含某行，只证明源码是源码。用受控输入运行脚本并断言输出、副作用或退出码。指导智能体的文档由消费智能体行为测试（superpowers:writing-skills）；面向人的文字不需测试。

**测试你的代码，不测框架。** 测试代码在边界建立的契约：注册的路由、发出的查询、产生的载荷。上游机制由其维护者测试（典型错误：断言路由器调用注册处理器）。上游行为确实令你意外时，写一个窄特征测试并命名假设。边界也适用于内部构造器、getter、常量、转发器；只有验证、规范化、默认、派生、强制执行或产生副作用时才测试，否则断言依赖它们的第一个消费者可见结果。

### 关卡函数

```
编写测试主体前：
  说出会让测试失败的生产变更。

  无法说出 → 围绕可观察行为重设计
  “源文本变了” → 运行产物并断言其效果
  只有有意决策 → 变更检测器；测试依赖该决策的行为
                               

  确认期望值在没有被测代码的情况下推导。
  如果复用代码逻辑或辅助函数：
    替换为字面量或手工核验夹具
```

## 原则 2：测试真实对象

**mock 本身得不到断言。** mock 断言在 mock 存在时通过、缺席时失败，无关于组件。断言真实组件行为；正在检查 mock 时，取消 mock 或删除断言。

```typescript
expect(screen.getByRole('navigation')).toBeInTheDocument();
expect(screen.getByTestId('sidebar-mock')).toBeInTheDocument();
```

**你的人类伙伴的纠正：**“我们在测试 mock 的行为吗？”

**在正确层级 mock。** 替换前了解真实方法的每个副作用；只 mock 慢或外部操作，保留测试依赖的真实部分。不确定时先在真实实现上运行测试并观察实际需要发生什么。

```typescript
vi.mock('ToolCatalog', () => ({
  discoverAndCacheTools: vi.fn().mockResolvedValue(undefined)
}));
vi.mock('MCPServerManager');
```

**让替身具体。** 参数、调用次数或顺序属于契约时断言它们；接受任何内容的假实现什么也不验证。为成功、错误、畸形分支分别设置夹具或 spy，使错误分支不能满足期望。

**完整映照真实数据。** mock 真实存在的完整结构，包括所有文档化字段，不只是测试读取的字段。下游读取遗漏字段时部分 mock 会静默失败，测试通过而集成破坏。

**生产类只带生产方法。** 仅测试需要的清理放在测试工具中，绝不在生产类上添加 `destroy()`。询问：此方法只从测试调用吗？类拥有资源生命周期吗？答案不对就用测试工具。

**优先真实组件而非复杂 mock。** mock 设置超过测试逻辑、mock 漏掉真实组件方法，或 mock 变化导致测试失败时，改用真实组件集成测试。**你的人类伙伴的问题：**“这里需要用 mock 吗？”

### 关卡函数

```
添加 mock 或测试辅助前：
  列出真实方法副作用；保留测试
  依赖的真实部分——mock 其下慢／外部层级。

  mock 响应映照完整真实结构。

  只由测试调用的方法放测试工具，不放生产代码。

  即将对 mock 自身断言？
    取消 mock 或删除断言。
```

## 测试随实现交付

TDD 循环——失败测试、最小实现、重构——就是“完成”的含义。只交付行为需要且必要的测试：平凡代码和人类文字无需测试，为满足流程而写的测试会永久增加维护成本。

## 变异检查

完成前在心里变异生产代码；每个现实变异至少应让一个测试失败：

- 错误常量或参数

- 错误分支处理器

- 缺失状态变化或副作用

- 空或默认返回

- 缺少零值、空值、nil、未授权或畸形输入验证

没有测试捕捉的变异说明行为未受保护，或测试是同义反复。

## 快速参考

| 当你…… | 要做 |
|---|---|
| 编写任何测试 | 说出它捕捉的破坏——是 bug，不是决策 |
| 构建期望值 | 手工推导；绝不用被测代码 |
| 测试脚本或文档 | 运行它／压力测试消费者；绝不 grep 文本 |
| 想测试依赖 | 测试你的边界契约，不测其文档化机制 |
| 想断言 mock 元素 | 测试真实组件或取消 mock |
| 即将 mock 方法 | 了解副作用；mock 慢／外部层级 |
| 构建 mock 响应 | 完整映照真实结构 |
| 需要仅测试使用的清理 | 放入测试工具 |
| mock 设置膨胀 | 改用真实组件集成测试 |
| 完成测试文件 | 运行变异检查 |

## 警告信号

- 设置与断言共享同一对象，保证相等

- 测试只能因 panic、崩溃或选择器缺失失败

- 每次有意变更都失败，意外破坏时从不失败

- 期望值藏在循环、构建器或辅助函数后

- 测试 grep 源码，或断言移除符号仍移除

- 只剩框架时测试仍似乎有意义

- 测试只为覆盖率，无副作用或结果检查

- 断言检查 `*-mock` 测试 id，删除 mock 就失败

- 方法只从测试文件调用

- mock 设置超过测试一半，或无法解释为何需要 mock

- “以防万一”地 mock
