# 阶段边界

**阶段**是会话内一块工作：访谈、实现、QA。定义有意模糊：当你想“好，这部分完成了”，阶段就结束。

**阶段边界**是两个阶段之间的间隙，也是这种决策唯一适合的位置。阶段中途没有选择：继续，或把剩余工作拆给子代理。阶段中途压缩会让代理失去主线。

## 五个选项

| 选项 | 作用 |
| ------------ | --------------------------------------------------------------- |
| **继续** | 留在会话。完全不切换上下文。 |
| **`/clear`** | 清空上下文窗口，从零开始。 |
| **`/handoff`** | 写一个可移植 Markdown 文件，并在任何地方用它启动会话。 |
| **子代理** | 将任务送到自己的上下文窗口，并取回报告。 |
| **`/compact`** | 压缩当前上下文，用摘要启动全新会话。 |

## 决策树

在边界处从上到下判断。第一个**是**胜出。

**1. 能在本会话继续吗？**两件事使答案为是：下一阶段需要本阶段作为**一手来源**，或你有足够[智能区](https://www.aihero.dev/ai-coding-dictionary/smart-zone)（约 150k token）容纳下一阶段。访谈 → 实现是标准“是”：实现需要逐字推理，而非摘要。继续无成本、无损失，因此先排除其他选项。

**2. 上下文对接下来无关吗？**本会话中的一切（探索、决定、死路）都可丢弃吗？若是，**`/clear`**。这是棋盘上最便宜的移动：不花时间，归还整个窗口。`/clear` 也非终止：旧会话仍可恢复。

做错这一步的成本单向。清掉*相关*上下文，就失去所有构建背后的 **why**，再读多少差异都无法找回。

**3. 需要交接吗？**`/handoff` 范围很窄。仅在以下情况需要：

- 切换到**新宿主**（Claude → Codex），

- 迁到**新目录**或仓库，

- 把工作交给**同事**，

- 或把**阶段中途**发现的侧任务分叉出去且不打断当前工作。

这份清单就是完整条件。`/handoff` 买到的**可移植性**：一个可携带文件。若没有内容要移动，就不需要。

**4. 任务能离线完成吗？**范围是否足够紧，可在你离开键盘、无需指导下运行？若是，交给**子代理**，保留本会话不动。自动审查是标准情形：代理读取差异并报告，期间不需要你。

**5. 否则，`/compact`。**相关上下文、同一宿主、同一目录，而且你需要继续参与：这是树的落点，也经常落在这里。传入指令（`/compact we're going to QA this area`），让摘要保留下一阶段所需内容。

`/compact` 是**默认，而非首选**。它位于底部，因为上方四问都更便宜或更精确。从这里开始的失败模式是全新会话对摘要压平的决定自信地判断错误。

## 一手与二手来源

除**继续**外，每个移动都把**一手来源**变成**二手来源**：当时的会话被其摘要替换。权衡形式始终相同：

| 来源 | 信息 | 噪声 | 活动空间 |
| --------------------------------- | ----------- | ----- | ------------ |
| 一手（继续） | 完整 | 多 | 小 |
| 二手（`/compact`、`/handoff`） | 有损 | 更少 | 大 |

这就是问题 1 排在首位的原因。只有继续的成本超过节省价值时，才承担有损代价。

## 这些都是判断

这些问题并不客观：每个都含品味，同一边界在不同日期可有不同答案。价值在于**按顺序**在边界处提出，而不是在工作中途提出。
