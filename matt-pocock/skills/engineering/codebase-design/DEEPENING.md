# 深化

在给定依赖下安全深化一簇浅模块。使用 [SKILL.md](SKILL.md) 的词汇：**module**、**interface**、**seam**、**adapter**。

## 依赖类别

评估候选时，分类其依赖。类别决定深化模块如何跨接缝测试。

### 1. 进程内

纯计算、内存状态、无 I/O。总可深化：合并模块并直接通过新接口测试。无需适配器。

### 2. 可本地替代

有本地测试替代品的依赖（Postgres 用 PGLite，内存文件系统）。替代品存在时可深化。测试套件中运行替代品并测试深化模块。接缝是内部的；模块外部接口无需端口。

### 3. 远程但自有（端口与适配器）

跨网络边界的自有服务（微服务、内部 API）。在接缝定义**端口**（接口）。深模块拥有逻辑；传输作为**适配器**注入。测试使用内存适配器，生产使用 HTTP/gRPC/队列适配器。

建议形式：*“在接缝定义端口，为生产实现 HTTP 适配器，为测试实现内存适配器，让逻辑位于一个深模块中，即使跨网络部署。”*

### 4. 真正外部（Mock）

无法控制的第三方服务（Stripe、Twilio 等）。深化模块把外部依赖作为注入端口；测试提供 mock 适配器。

## 接缝纪律

- **一个适配器意味着假设性接缝，两个适配器意味着真实接缝。** 除非至少两个适配器合理（通常生产 + 测试），否则不要引入端口。单适配器接缝只是间接层。

- **内部接缝与外部接缝。** 深模块可有内部接缝（实现私有，由自身测试使用）及接口处外部接缝。不要仅因测试使用就把内部接缝暴露到接口。

## 测试策略：替换，不叠加

- 深化模块接口处已有测试后，浅模块旧单元测试成为浪费；删除。

- 在深化模块接口处写新测试。**接口就是测试表面。**

- 测试通过接口断言可观察结果，而非内部状态。

- 测试应经受内部重构，因为它们描述行为而非实现。实现变化就必须改测试，说明测试越过了接口。
