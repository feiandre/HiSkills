# 向导

**向导**是一段 bash 脚本，逐步引导人完成手工操作——这种操作手动做很繁琐，每次都向 AI 重新解释也很繁琐。脚本打开每个 URL，准确说明点击和复制什么，捕获值，将它们写到应在的位置（`.env`、GitHub secret），在每个阶段确认，并显示还剩多少阶段。它可以配置第三方服务、执行一次性迁移，或把项目从一种状态移动到另一种状态。

令人愉快的用户体验已由 [template.sh](template.sh) 解决：逐阶段进度、确认关卡、跨平台打开 URL（包括 WSL）、隐藏 secret 输入、幂等 `.env` upsert、写入 `gh secret`／`gh variable` 以及结束摘要。**你的工作只是界定流程范围并编写各阶段。** `STAGES` 标记上方的库在每个向导中完全相同；这种一致性正是重点：绝不手工修改它。

向导默认是临时性的：为一次运行构建，保存到临时位置或 `scripts/` 路径，完成后删除。只有当用户希望可重复的设置路径保留在仓库中时才提交它。

## 流程

### 1. 界定流程范围

找出人必须执行的每个手动步骤以及途中捕获的每个值。先阅读仓库，不要冷启动提问：

- 设置类任务：`.env`、`.env.example`、`.env.*`、`README`、`docker-compose*`、框架配置以及 `.github/workflows/*`（每一处 `secrets.*`／`vars.*` 引用都是向导必须产生的值）。

- 迁移或状态转换：当前状态、目标状态以及两者之间不可逆的操作。

然后向用户展示有序阶段列表以及每个阶段产生的值，并请其确认：他们可以添加、删除或重排。

**完成条件：** 每个阶段按顺序命名，并且对每个捕获值都知道：(a) 人从哪里得到它；(b) 写到哪里（`.env`、GitHub secret、两者，或哪里都不写；某些阶段只执行动作）；(c) 它是 secret（隐藏输入）还是公开值。

### 2. 梳理每个阶段的路径

为每个阶段写出人遵循的精确路径：打开哪个 URL、在里面做什么、值在哪里显示、填入哪个变量，例如“仪表板 → Developers → API keys → 显示测试密钥 → 复制”。如果不真正了解当前 UI 或准确命令，就明确说明并询问用户或查阅文档：绝不编造可能不存在的步骤。

**完成条件：** 每个阶段都能追溯到陌生人也能遵从的具体指令。

### 3. 编写向导

将 `template.sh` 复制到目标路径。按依赖顺序用每个步骤一个 `stage` 替换示例阶段。使用库辅助函数：`stage`、`say`/`step`、`open_url`、`ask`/`ask_secret`、`write_env`、`set_secret`/`set_var`、`pause`/`confirm`。将 `TOTAL_STAGES` 设置为所写阶段数量。

遵循模板设定的标准：请求值之前打开 URL；任何 secret 都使用 `ask_secret`；每个持久值都使用 `write_env`；只对 CI 实际需要的值使用 `set_secret`；任何不可逆操作前都 `confirm`。每个 `stage` 会清屏，只显示当前步骤：每个阶段保持一个聚焦任务，避免人需要的内容滚出屏幕。不要修改标记上方的库。

### 4. 验证并交付

- `bash -n <script>`；如果可用则运行 `shellcheck`。

- 使脚本可执行：`chmod +x <script>`。

- 不要自己端到端运行：它会打开浏览器并阻塞等待人的输入。改为静态追踪：第 1 步的每个值都被捕获并写到第 1 步所说的位置，每个 `set_secret` 名称都与 CI 中的 `secrets.*` 引用精确匹配。

- 告诉用户如何运行。如果这是可重复的设置路径，提交它并在 README 中链接，让下一个人运行脚本而不必询问 AI。
