# MISSION.md 格式

`MISSION.md` 位于工作区根目录，记录用户学习此主题的_原因_。每个教学决定（接下来教什么、提供什么资源、设计哪些练习）都应能追溯到本文件。

## 模板

```md
# 使命：{主题}

## 为什么
{1—3 句话。用户追求的具体现实目标。掌握此技能后，生活或工作会有什么变化？避免“理解 X”等抽象表述；追问背后的结果。}

## 成功的样子
- {用户将能完成的一件具体、可观察的事}
- {另一件具体的事}
- {…}

## 约束
- {时间、预算、已有承诺、学习偏好，以及任何限定方法的条件}

## 范围之外
- {用户当前明确不想涉足的相邻主题，保护最近发展区}
```

## 规则

- **每个工作区一个使命。** 用户想学两件无关的事，就用两个工作区。
- **具体优先于抽象。** “十月前跑完半马”胜过“更健康”。“交付一个供团队使用的 Rust CLI”胜过“学习 Rust”。
- **反对含糊。** 用户说不出原因时，先访谈，再写任何内容。糟糕使命比没有使命更糟。
- **现实变化就修订。** 使命会改变。用户目标变化时更新此文件，不要让陈旧使命引导未来会话。
- **保持简短。** `MISSION.md` 超过一屏时，就不再是指南针，而变成了计划。
