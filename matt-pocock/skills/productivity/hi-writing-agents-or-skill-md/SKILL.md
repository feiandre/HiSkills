本文是编写任何供代理[AGENT]读取的文档时的参考：技能、`AGENTS.md` / `CLAUDE.md`，或经由指针访问的文档。包装方式不同，写法却相同：同样的调节手段能让它们变得可预测，因为代理每次运行都采用相同的**过程**，而不是生成相同的输出。

如果正在编写的文档是一项技能，请阅读 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)，了解 frontmatter、调用方式的选择以及路由技能。

## 上下文指针

**上下文指针**是保存在代理上下文中的引用，它为某份上下文之外的材料命名，并编码访问它的条件。技能的 description 就是一个指针；`AGENTS.md` 中点名某份文档的一行，也是同一种对象。决定代理何时访问材料、访问有多可靠的，是指针的**措辞**，而非它的目标。必读的目标藏在措辞薄弱的指针之后，会造成行为波动问题：先强化措辞，只有强化无效时才把材料内联。

指针有两个任务：说明材料是什么，并列出应触发访问它的**分支**（分支是文档处理的一种独立情形，所以不同运行会走不同路径）。始终加载的指针中，每个词在每轮对话都会产生成本，因此它比正文更值得严格精简：

- **将引导词前置**：指针正是引导词发挥触发作用的位置。
- **每个分支一个触发条件。** 给同一分支换个名字的同义表达，相当于把一个分支写了两遍；将它们合并，只保留真正不同的分支。
- **删除正文已经承载的身份说明。**

## 两种负载

你添加的每份文档和每个指针，都会消耗两种预算之一：

- **上下文负载**：始终加载的材料对代理上下文窗口造成的成本，包括 `AGENTS.md` 的一行、技能 description，以及每轮都留在上下文中的任何内容；无论是否触发，都消耗 token 和注意力。
- **认知负载**：人类承担的成本，即有哪些文档，以及何时应使用哪一份。人类就是索引。这不是要尽可能压低的成本，而是人类自主性的代价；在人类判断有价值的地方投入，在不需要人类判断的地方去除。

仅经由指针访问的材料，以指针自身一行的代价避开上下文负载；完全没有指针的材料，则全部依靠认知负载。

## 信息层级

文档由两类内容构成：**步骤**（代理按顺序执行的动作）和**参考**（按需查阅的定义、规则、事实）。二者可以自由组合：全是步骤（操作配方）、全是参考（审查规则、本技能），或兼有两者。核心决策是每部分应位于**信息层级**的哪里；这是一架按代理多么迫切需要材料来排序的阶梯：

1. **文件内步骤**是首要层级：代理按顺序做什么。
2. **文件内参考**供按需查阅。它常常是一组合理的平级内容（审查的每条规则都在同一级），这种安排完全可以，并非坏征兆。
3. **外置参考**被移到单独文件中，经由上下文指针访问，只有指针触发时才加载。其范围可以从同目录的兄弟文件，一直到完全外部、位于任何地方且任何文档都能指向的参考材料。

向下移动得太少，顶部就臃肿；移动得太多，又会把代理实际需要的材料藏起来。这种张力就是整个决策的关键。

**渐进披露**是沿阶梯向下移动（移出主文件，置于指针之后），以保持顶部可读。它首先不是 token 优化，而是保护信息层级的方式。分支是最清晰的披露判断标准：每个分支都需要的内容内联，只有某些分支才访问的内容放到指针之后。文档包含步骤时，本应外置的文件内参考会埋没步骤，让代理是否关注步骤变得像抛硬币一样不确定：这影响的是行为稳定性，而不只是可读性。

**就近放置**是文件内部的配套原则：阶梯决定一份内容放在**多低**，就近放置决定到了那一级后，**什么内容放在它旁边**。一个概念的定义、规则和注意事项应放在同一标题下，而不是散落各处，这样读到其中一部分就能同时读到相邻内容。判断标准是：文档读起来应像专为代理编写的文档。归组后的材料如此，散落的材料则不然。（这与重复不同：重复是在两处表达同一个含义；散落是把一个含义拆碎到许多地方。）

**蔓延**是这里的失败模式：即使每一行仍有效且不重复，文档仍然太长。过多内容稀释注意力，每多一行，就多一行要维护其相关性。解法就是这架阶梯：把参考移到指针后面，按分支或顺序拆分，让每条路径只携带自己需要的内容。

## 步骤与完成标准

每个步骤都以一个**完成标准**结束，即告诉代理工作已完成的条件。两种属性使它成为调节手段：

- **清晰度**：代理能否区分完成与未完成？模糊的界限（“已达成理解”）会诱发**过早完成**：步骤尚未真正完成就结束，注意力滑向“已经做完”这件事。仍在眼前的后续步骤（**完成后的步骤**）提供拉力；标准的清晰度提供阻力。按顺序防御：**先明确界限**（局部且便宜）；只有界限确实无法避免模糊，**并且**观察到抢跑时，才通过拆分顺序来隐藏后续步骤。隐藏只有跨越真正的上下文边界才有效（交接或派发子代理；内联调用仍把后续步骤留在上下文中，什么都没有清除）。
- **要求强度**：标准要求多少。“每个修改过的模型都有交代”能强制细致工作，而“生成一份变更清单”做不到。要求强度驱动**深入查找**（代理在工作中进行的挖掘，它潜藏于措辞，而不是单独写成步骤），而且不限于步骤：“应用每条规则”约束一整组平级参考，正如“完成每个步骤”约束一个序列；这也解释了全是参考的文档如何仍然承载穷尽性要求。

最强的标准既可检查，又覆盖完整。

## 何时拆分

把一份文档拆成两份，会消耗两种负载之一，因此只有拆分收益值得时才拆：

- **按顺序拆分**：如果完成后的步骤诱使代理仓促结束当前步骤，就在这串步骤中拆开。把它们移出视野，会促使代理在当前任务上进行更多深入查找。也要留意反向作用：合并序列，会暴露各步骤之后还有哪些步骤，诱发过早完成。
- **按调用拆分**，技能特有：参见 [`SKILL-MECHANICS.md`](SKILL-MECHANICS.md)。

## 引导词

**引导词**是模型预训练中已经存在的紧凑概念，代理运行文档时借它思考（如 _lesson_、_fog of war_、_tracer bullets_）。反复出现的是一个词元，而不是一个句子；它积累起分布式定义，利用模型已有的先验知识，以最少 token 锚定一整片行为。自己造词也可以，只要定义清晰；但自造词无法借用先验知识：预训练词免费提供的东西，你要用定义 token 付费，所以应先找现成词。

它有两重锚定作用。在正文中，锚定**执行**：每次出现该词，代理都采用同样的行为；在平级参考中，它把注意力聚焦到应寻找的一类事物。在指针中，锚定**调用**：当同一个词同时出现在提示、文档和代码库中，代理会把这套共同语言与材料关联起来，更可靠地访问它。

寻找用引导词重构的机会。三元组合在三个位置逐字展开，或者指针用整句话指向一个想法；每处都是渴望被压缩为单一词元的段落：

- “快速、确定性、开销低” → _tight_（一个 _tight_ 循环）。
- “你相信的循环” → _red_，把模糊的门槛转成可观察的二元状态（该循环在遇到缺陷时变为 _red_，或者没有变红）。

你会得到双重收益：token 更少，代理挂靠思考的锚点也更明确。应假定每份文档里都有可由引导词取代的重复陈述，去把它们找出来。

**否定**是这一手段旁边的失败模式：用禁令引导会把被禁止的行为拖入上下文，使它**更**容易被想到，而非更少。“不要想大象”，结果脑中只剩大象；否定是弱修饰语，会被强烈激活的概念压倒，于是禁令有一半读起来像让代理去做这件事。应以**肯定方式**提示：陈述目标行为（“编写单行注释”），让被禁止的行为从未被说出。只有无法用肯定方式表达的硬性护栏，禁令才值得保留；即便如此，也要搭配肯定目标，让注意力落在该做什么上。

## 精简

- 让每个含义都保存在**单一事实来源**中：只有一个权威位置，这样修改行为只需改一处。**重复**（同一含义出现多处）消耗维护成本和 token，还会把该含义在阶梯中的显著性抬高到超出其真实级别。（它恰好是引导词的意外反面：引导词有意重复的是一个词元，而不是含义。）
- **环境**也是事实来源（`package.json` 脚本、配置文件、目录布局、`--help` 输出），复述这些内容的文档就是**缓存**：一份查询结果的副本，只有查询昂贵时才值得承担其负载。缓存代理靠查看找不到的东西：未成文的约定、选择背后的原因、任何配置都没揭示的陷阱。只需一个文件或一条命令就能查到的内容留给环境，以免过时。
- 检查每行的**相关性**：它是否仍与文档所做的事情有关？一行文字可能因从未与任务有关（纯粹铺陈，或本应外置的分支），或者因其描述的行为或世界已改变而过时，从而失去相关性。短文档更容易保持相关性。若缺少精简纪律，默认归宿就是**沉积层**：因为添加让人感觉安全、删除让人觉得冒险，过时层次不断沉积，直到必须向下钻取才能找到仍然有效的内容。
- 逐句寻找**无效指令**：模型默认已经遵守的指令，只付出负载却没有产生作用。判断标准（与默认行为相比是否改变了行为？）取决于模型，而非读者：两个人对某句是否无效持不同意见，其实是在争论默认行为，应通过运行文档解决，而不是辩论。如果一句话未通过判断，应删除整句，而不是只精简其中几个词。这个判断也适用于引导词：太弱、无法超越默认行为的词（代理本来就已经有些细致时，要求 _be thorough_）也是无效指令；修正方式是用更强的词（_relentless_），而非换一种技巧。
