# 解释数字

- **运行前写下决策。** 指明什么结果会改变决策，以及噪声下限。运行间波动大于效果时停止。

- **问“为什么不能好一倍？”** 指出限制结果的资源或代码路径，例如一个核心、一把锁、磁盘、网络或负载生成器本身。从运行中的性能剖析或系统计数器获取，再映射到源码。阅读代码所得猜测不是限制因素。如果不能解释数字为何不能好一倍，就不知道自己测了什么。

- **列出这个数字还可能在测什么，并用证据逐一排除。** 常见嫌疑包括错误、跳过或缓存的工作、从未运行的代码、未调优的一方（保留默认设置）、噪声，以及小到不影响端到端结果的部分。

- **证据与数字一起保存。** 在笔记或链接制品中记录运行次数、波动范围和限制因素。

对性能数字，使用 [benchmark-checklist](../benchmark-checklist/SKILL.md) 技能运行完整流程。对评估结果，也对各试验提出同样问题：每次运行都完成任务了吗？差距能跨试验及模型维持吗？场景有实际意义吗？

如果运行开始前没有说明会改变决策的结果，数字背后的证据没有运行次数、波动范围或明确限制因素，或者节省时间大于所改部分原耗时，就说明跳过了本原则。

它不同于 [Prove It Works](../principle-prove-it-works/SKILL.md)，后者检查输出是否真实。
