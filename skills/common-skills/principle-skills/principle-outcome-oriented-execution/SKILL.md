# 以结果为导向执行

为预期且可验证的最终状态优化，而非维持平滑的中间状态。

**原因：** 保持每个中间步骤完全稳定，往往会产生临时兼容代码，并演变为长期债务。收敛到目标架构，在明确的验证边界证明正确性。

**核心规则：**

- 最终状态完整性优先于过渡期稳定性

- 有计划、范围受控且可逆时，可以接受中间状态损坏

**护栏：**

- 用于具有明确阶段边界的计划性重写和迁移

- 声明哪些地方允许暂时损坏

- 迁移期间，对正在改动的区域保留高信号检查

- 计划完成时，要求完整静态验证及运行时验证
