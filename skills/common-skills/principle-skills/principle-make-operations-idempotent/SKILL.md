# 使操作幂等

将操作设计成无论运行多少次、上一轮在哪里停止，都收敛到正确状态。每个修改状态的操作都应回答：“若运行两次会怎样？若上次运行中途崩溃会怎样？”

**为什么：**命令、生命周期操作和处理循环在崩溃、重启、重试属于常态的环境运行。若部分状态改变下次结果，每次重启都会变成调试会话。

**思想：**每个步骤都从现有状态派生，而非从上一轮打算做什么派生。读取当前状态、与目标比较，只应用差异。这样编写的步骤可安全重复，因为重复时已无剩余工作。

运行留下的任何内容，例如锁、临时文件、半写记录或已领取任务，必须能被下一轮识别为过期。按无论上一轮在何处停止都仍然成立的证据判断过期，而不只考虑常见情形。下一轮无法判断的标记会让每次崩溃都需手工清理。例如写入临时路径后重命名到最终位置，或按内容而非创建顺序比较制品。

**测试：**

1. 连续运行两次会怎样？

2. 上一轮在每个可能点崩溃会怎样？

3. 重新执行是否收敛到相同最终状态？

若任一答案是“取决于留下了什么状态”，该操作需要协调步骤。
