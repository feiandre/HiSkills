# 测试行为，不测试实现

测试是对代码为其使用者做什么的声称，使用者可以是调用者、最终用户或其他服务。行为是这些使用者通过所用接口能够观察到的内容，包括返回值、错误、可读取的状态，以及对代码外系统的影响，例如发送请求、写入行或发出消息。实现是他们无法观察的内容：私有辅助函数、内部调用顺序、中间数据，以及哪个内部协作者完成工作。

用两个假想编辑评判每个测试：

- **破坏行为。** 让代码返回错误值、跳过某个效果，或执行两次效果。如果测试仍通过，它什么也证明不了。常见原因是断言比契约更宽松、预期值由被测代码计算、重述常量或提示词字符串却未运行读取它的代码，以及对测试自行构建的数据作断言。

- **改变内部。** 保持所有可观察结果一致，重组底层代码。如果测试此时失败，它就绑定到了实现。每次重构都要重写，却仍无法捕获 bug。

保留能捕获第一种编辑且经受第二种编辑的测试。其余重写或删除。要同时做到这两点，通过使用者的接口用具体输入驱动代码。根据需求推导预期值，而不是运行代码获得。断言契约承诺的内容，不多也不少。

由契约决定，而非断言形式。如果承诺是“空购物车绝不扣款”，那么断言支付客户端未被调用就是行为。搭配一个实际扣款的案例，使测试表明自己能看到调用。mock 外部服务收到的载荷属于行为，因为那个服务能观察到它。对内部辅助函数的调用属于实现，因为没有使用者能看到。没有记录匹配时，空列表就是精确答案；如果测试只需要某个结果，空列表检查则是空洞的。精确错误消息会绑定没有调用者读取的措辞。调用者据以分支的错误类型才是契约。

测试也可以固定不变量，而非调用，例如某个键必须存在于两张表中，或编译时类型检查。不变量就是行为。
