# 修复根因

调试时修复故障，而非它显现的位置。症状是错误状态变得可见的地方。根因是系统第一次做了不该做的事，或未处理本应处理的状态的位置。

**原因：** 症状修补会隐藏证据，让故障仍可在别处显现。每次这样做都会使系统更难推理，因为代码现在带着一个无人明确指出的 bug 的变通方案。

**模式：**

- 先复现。

- 每步问“为什么”，直到答案是代码中的错误决定，而非更早错误的后果。

- 卡住时增加观测手段。读取实际错误和实际状态。不要猜测。

- 问触发症状的状态是否合法。如果系统可能处于该状态，那么在此状态下出错的代码就是根因，在那里处理状态就是修复。如果该状态本不应存在，在出错处加检查只会隐藏 bug。找到产生该状态的地方。守卫、重试、吞掉错误、钳制数值和丢弃状态，是隐藏 bug 的常见方式。

- 某事只在重启后失败时，先怀疑持久化状态：配置文件、缓存、锁文件、序列化状态。

- 查找模式，而不只看实例。找出具有相同故障的每个地方，并全部修复。

- 如果某个变通方案需要一整段注释才能辩解，代码就是错的。修复代码，不修饰注释。

- 如果决定性事实需要深挖才找到，提出一种低成本、始终启用的信号，使它一开始就能被看见。
