# 体验优先

实现便利与用户满意冲突时，选择用户满意。

- 每个功能、控件和选项都必须有理由

- 少做，做好：三个功能的精致体验，胜过十个功能的粗糙体验

- 承诺实施前先做原型：在可丢弃 HTML 中作设计决策，比在生产代码中更便宜

- 做对细节：过渡、对齐、间距、反馈、错误状态

- 收紧核心循环：每个功能都应服务于核心工作流，或不妨碍它

用户就是使用工作成果的人。对 UI，是最终用户；对库或内部 API，是导入它的同事。下一位维护代码的工程师也是用户。同样权衡他们的体验，并从他们的视角解释影响。

基础应服务于体验。基础性思考决定工作的*顺序*。本原则决定*目标*。
