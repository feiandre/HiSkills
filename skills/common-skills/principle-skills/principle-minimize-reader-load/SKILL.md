# 降低读者负担

可维护性是读者理解代码所需的工作。追踪两条轴：**追溯层级**（问题与答案之间的间接层）和**保持状态**（读者必须记在脑中的隐藏或可变上下文）。代码行数、圈复杂度和“整洁架构”都是代理指标，读者负担才是关键。两轴相互独立。一个含 50 个全局变量的扁平文件，可能和六层适配器栈一样难推理。两者都要防范。这是 [Guard the Context Window](../principle-guard-the-context-window/SKILL.md) 的人类对应物。读者的工作记忆同样有限。

- **合并成本高于收益的层**：只有一个调用者的包装器、没有第二实现的适配器、从未需要的推测性间接。将它们内联。

- **让相邻层改变抽象。**重复相同方法和参数的层只会增加读者负担而没有任何压缩。合并直通层。

- **要求接口压缩。**大接口隐藏很少复杂度，会迫使读者同时学习表面和实现。优先选择隐藏有意义决策的边界。

- **缩小状态作用域：**优先纯函数（返回而非修改）、局部变量胜于字段、字段胜于模块状态、模块状态胜于全局变量。派生而非同步。

- **在边界处命名不变量**，而非每个消费者，使读者只学一次。

- 添加一层或一份状态前询问：它是否至少等量降低其他地方的读者负担？

**测试：**新读者能否在 30 秒内回答“X 从哪来？”和“什么能改变 X？”若不能，减少层或状态。
