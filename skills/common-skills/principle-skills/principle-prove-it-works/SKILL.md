# 证明它有效

直接检查真实对象，验证每个任务的输出。不要根据替代指标、自述或“能编译”来推断。

**原因：** 未验证工作的正确性是未知的。间接验证（文件修改时间、输出新鲜度、代理自述、缓存截图）似乎比直接观察便宜。依据错误推断采取行动，其代价远高于检查源头。

检查真实对象，而不是替代指标：

- 直接检查进程是否存活，不要通过派生状态间接判断。

- 读取实际值，而不是缓存或派生表示。

- 验证失败时，先怀疑观察方法，再怀疑系统。

## 能写成脚本时，就用脚本检查

最有力的证据是一个可确定性地重新运行同一比较的脚本，而不是一次性的目测。编写脚本、运行它，并保留输出作为产物，让审查者可以重新运行，而不必相信你的口头保证。

让人类能看见这个产物。只有当工作大型或复杂、将来必须审计过程时，才把它提交，例如大型移植或迁移（**show-me-your-work** 技能）。
